# 代码审查技能 🔍

## 何时使用
- 需要检查代码质量时
- 需要发现潜在bug时
- 需要优化代码性能时
- 需要遵循最佳实践时
- 需要代码风格统一时

## 何时不使用
- 代码已经过充分测试
- 代码符合团队规范
- 代码已经过专业审查

## 输出格式
- 审查报告
- 问题列表
- 改进建议
- 代码示例

## 使用流程
1. 读取代码文件
2. 分析代码结构
3. 检查代码质量
4. 识别潜在问题
5. 提供改进建议
6. 生成审查报告

## 示例场景

### 场景1：审查函数实现
用户请求："审查这个函数的实现"
执行步骤：
1. 分析函数逻辑
2. 检查错误处理
3. 检查边界条件
4. 检查性能问题
5. 提供改进建议
6. 生成审查报告

### 场景2：审查项目结构
用户请求："审查项目代码结构"
执行步骤：
1. 分析目录结构
2. 检查模块划分
3. 检查依赖关系
4. 检查代码组织
5. 提供重构建议
6. 生成结构报告

### 场景3：审查安全性
用户请求："检查代码安全性问题"
执行步骤：
1. 检查输入验证
2. 检查SQL注入风险
3. 检查XSS漏洞
4. 检查认证授权
5. 提供安全建议
6. 生成安全报告

## 工具依赖
- `file_read`: 读取代码文件
- `file_list`: 列出项目文件
- `shell_execute`: 运行linter工具
- `text_analyze`: 分析代码文本

## 注意事项
- 保持客观公正
- 提供具体建议
- 考虑项目背景
- 尊重团队规范
- 区分优先级
- 提供示例代码

- 使用代码检查工具
- 遵循编码规范
- 关注可维护性
- 考虑性能优化
- 检查错误处理
