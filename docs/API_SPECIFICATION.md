# 统一API接口规范

## 1. API基础规范

### 1.1 版本控制
- 所有API端点必须包含版本号，格式为 `/api/v{version}/`
- 当前版本：`v1`

### 1.2 内容类型
- 请求和响应默认使用 `application/json` 格式
- 所有文本使用UTF-8编码

### 1.3 认证
- 使用Bearer Token认证：`Authorization: Bearer {token}`
- 某些端点可能不需要认证

## 2. 响应格式

### 2.1 成功响应
```json
{
  "code": 200,
  "message": "Success message",
  "data": {},
  "timestamp": 1640995200000,
  "requestId": "unique-request-id"
}
```

### 2.2 错误响应
```json
{
  "code": 400,
  "message": "Error message",
  "details": "Detailed error information (optional)",
  "timestamp": 1640995200000,
  "requestId": "unique-request-id"
}
```

### 2.3 状态码定义
- `200`: 成功
- `400`: 请求错误
- `401`: 未授权
- `403`: 禁止访问
- `404`: 资源不存在
- `422`: 参数验证失败
- `500`: 服务器内部错误

## 3. 端点列表

### 3.1 健康检查
- **GET** `/health`
- 无需认证
- 返回服务健康状态

### 3.2 消息处理
- **POST** `/api/v1/message`
- 无需认证
- **请求体**:
```json
{
  "sessionId": "string",
  "content": "string"
}
```

### 3.3 会话管理
- **GET** `/api/v1/session/{sessionId}`
  - 无需认证
  - 获取指定会话信息

- **GET** `/api/v1/sessions`
  - 无需认证
  - 获取所有会话列表

- **DELETE** `/api/v1/session/{sessionId}`
  - 无需认证
  - 关闭指定会话

## 4. 错误处理

### 4.1 错误分类
- **客户端错误** (4xx): 请求参数错误、认证失败等
- **服务端错误** (5xx): 服务器内部错误、依赖服务不可用等

### 4.2 错误消息
- 错误消息应清晰描述问题
- 不暴露敏感的系统信息
- 提供足够的信息帮助调试

## 5. 日志记录

### 5.1 请求日志
- 记录请求ID、方法、路径、IP地址、用户代理
- 记录响应状态码、处理时间

### 5.2 错误日志
- 记录错误详情、堆栈跟踪（生产环境除外）
- 记录关联的请求ID

## 6. 安全规范

### 6.1 输入验证
- 所有输入必须验证
- 防止注入攻击
- 限制请求大小

### 6.2 输出编码
- 敏感数据脱敏
- 防止XSS攻击

## 7. 性能要求

### 7.1 响应时间
- 95%的请求应在2秒内响应
- 99%的请求应在5秒内响应

### 7.2 并发处理
- 支持至少100个并发连接
- 实现适当的限流机制

## 8. 监控指标

### 8.1 基础指标
- 请求总数
- 错误率
- 响应时间分布
- 活跃会话数

### 8.2 业务指标
- 消息处理成功率
- 会话创建/关闭统计
- 工具调用统计
